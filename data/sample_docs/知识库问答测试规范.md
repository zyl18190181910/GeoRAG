# 知识库问答测试规范

知识库问答系统应验证资料导入、文本分块、检索、回答生成、引用和拒答等环节。接口测试需要覆盖正常请求、空问题、字段缺失、错误文件、超大文件和无相关资料等场景。

回答质量不能只用字符串完全一致来判断。可以检查返回状态、字段结构、引用是否存在、引用是否支持结论、回答是否偏离问题，以及资料不足时是否正确拒答。

接口契约测试应检查 HTTP 状态码、字段名称、数据类型、必填字段和错误信息。相同输入重复提交时，还需要验证系统是否按设计替换、去重或保持幂等。

评测集应将调优集与最终测试集分开。调优集用于选择分块大小、重叠长度、检索数量和拒答阈值；最终测试集用于报告结果，避免反复调参导致评估偏高。

检索评测可以统计 Source Hit@K，即期望资料是否出现在前 K 个结果中。拒答评测需要同时包含应该回答和应该拒答的问题，防止系统通过一律拒答获得表面上的高准确率。

性能测试至少记录平均延迟和高分位延迟，并分别观察资料导入与问答接口。并发请求增加时，需要关注错误率、吞吐量和响应时间变化。

缺陷记录至少包含问题标题、环境、输入、复现步骤、实际结果、预期结果和严重程度。修复后应执行回归测试，并记录修复版本与复测结论。

每次评测应保存代码版本、知识库版本、评测集版本、参数配置和结果文件。日志中要包含请求标识和耗时，但不能记录密钥、完整隐私数据或不必要的原始文件内容。
